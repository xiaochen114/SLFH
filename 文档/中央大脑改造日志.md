## 2026-08-04：功能完善（11 个 commit）

### 一、系统 ID 机制（机器人身份）

机器人注册时由中央大脑分配**系统 ID**（`品牌-时间戳`），不信任机器人自报名：

```
绝影-20260804-143025    ← 机器狗 (dog)
大疆-20260804-143025    ← 无人机 (drone)
```

- **唯一性**：品牌+时间戳到秒，同秒多台加序号兜底
- **品牌映射**：dog→绝影 / drone→大疆 / other→设备
- **指令标签路由**：每条指令带 `robot_id`（收件人标签），按标签下发到指定机器人
- **先连后注册**：机器狗 connect 成功才注册，避免"僵尸机器人"

### 二、指挥台（Web 前端）

新增"指挥台" Tab，5 个模块：

| 模块 | 功能 |
|------|------|
| LLM 状态卡 | 在线/降级/连续失败/最后成功 |
| 调度流水 | 事件→LLM→指令 实时滚动（SSE）|
| 操作员↔LLM 对话 | 连续对话，带决策记忆，指令半自动待确认 |
| 待确认指令 | 对话生成的指令，操作员确认后下发 |
| 人工干预 | 手动下发指令（急停二次确认）|

### 三、多路视频流检测

单个 YOLO 模型共享检测多路视频源：

```
本机摄像头(0) ─┐
RTSP摄像头2  ─┼→ 共享单YOLO → 每路独立结果 + 标注帧
预录视频3    ─┘
```

- 视频源支持：本机摄像头 / RTSP / 视频文件
- 任意一路报警 → 触发紧急事件
- 检测结果带 `source_id` 标签区分来源
- 指挥台可切换查看各路画面

### 四、LLM 调度（核心改进）

**决策异步化**
- 调度循环**不再同步调 LLM**（避免 API 超时卡死主循环）
- LLM 决策在**后台线程**执行，调度循环 2 秒一跳始终响应

**高危三件套（不依赖 LLM）**
检测到火情等高危事件（priority≥2）时立即执行：
1. **急停所有机器狗** — 硬逻辑，不等待 LLM
2. **报火警** — SSE `fire_alarm`，前端全屏红色声光报警
3. **记录事件** — 数据库留档

### 五、告警双通道

```
检测到告警
    ↓
SSE 即时广播（1ms 推前端，不阻塞）   ← 即时通道
    ↓
异步线程写 alerts 表                 ← 持久通道
    ↓
分级清理：error保留30天 / warning保留7天
```

### 六、运维自愈检查修复

- `_执行修复` 尊重诊断器声明的"级别"字段（高危 → 人工确认）
- `_LLM诊断` 建议命令按闸门动态判定级别
- 自愈触发链接通（监控告警 → robot_issue → 自愈）
- 自愈历史持久化（合并数据库+内存）

### 七、数据隔离原则

| 数据 | 存储 | 说明 |
|------|------|------|
| 机器人实时状态 | 内存 `_robots` | 毫秒级，变了就用 |
| 事件/决策/告警/对话 | 数据库 | 持久，可回看 |
| SSE 队列 | 内存（有界500）| 防泄漏 |

## 2026-08-03：基础链路打通（12 个 commit）

### 一、接入大模型 API

- `brain_llm.py` 接入 OpenAI 兼容 API（DeepSeek/内网算力）
- 配置在 `配置.yaml` 的 `llm_api_url/key/model`
- LLM 做调度决策，规则引擎作为降级

### 二、接通 YOLO 火情检测 → 调度链路

- `检测服务.py` 包装 PerceptionSystem，检测结果写事件库
- 事件 → LLM 决策 → 下发指令的完整链路打通
- **修复火情检测语法 bug**：`__init__` 缺逗号导致模块无法加载

### 三、事件数据库化 + 标签

- 事件存 `events` 表，带 `source`/`type`/`label` 标签
- 中央大脑按标签即取即用（`取未消费事件`）
- **事件紧急度**：0=普通 / 1=紧急 / 2=特急，特急事件硬急停

### 四、LLM 降级机制

- 请求超时 8s，防止调度循环卡死
- 连续失败 2 次 → 降级规则模式
- 后台每 30s 重连，恢复自动切回
- 状态持久化，前端顶栏显示"LLM 降级中"

### 五、运维自愈系统

- **诊断器注册表**：绝影 / 感知主机
- **规则诊断优先**：ping/查服务/查数据
- **两级闸门**：低危自动 / 高危人工确认
- **LLM 增强**：规则无结论时 LLM 给修复命令
- 修复 `_LLM诊断` 死代码 bug（原恒返 None）

### 六、指挥台基础

- 新增指挥台 Tab（LLM 状态卡 + 调度流水 + 对话窗 + 待确认 + 干预区）
- 修复对话硬编码"已理解"问题，LLM 真实回复

### 七、其他

- 主控与中央大脑合并，入口统一
- 桌面端移入旧版
- 数据库移出 git 跟踪
- 支持克隆即跑（路径相对化）
