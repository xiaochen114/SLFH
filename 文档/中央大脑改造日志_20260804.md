# 中央大脑改造日志 — 2026-08-04

> 本文件记录 2026-08-04 中央大脑系统的全部功能改动，用于追溯和回滚参考。

## 一、系统 ID 机制（机器人身份）

机器人注册时由中央大脑分配**系统 ID**（`品牌-时间戳`），不信任机器人自报名：

```
绝影-20260804-143025    ← 机器狗 (dog)
大疆-20260804-143025    ← 无人机 (drone)
```

- **唯一性**：品牌+时间戳到秒，同秒多台加序号兜底
- **品牌映射**：dog→绝影 / drone→大疆 / other→设备
- **指令标签路由**：每条指令带 `robot_id`（收件人标签），按标签下发到指定机器人
- **先连后注册**：机器狗 connect 成功才注册，避免"僵尸机器人"

## 二、指挥台（Web 前端）

新增"指挥台" Tab，5 个模块：

| 模块 | 功能 |
|------|------|
| LLM 状态卡 | 在线/降级/连续失败/最后成功 |
| 调度流水 | 事件→LLM→指令 实时滚动（SSE）|
| 操作员↔LLM 对话 | 连续对话，带决策记忆，指令半自动待确认 |
| 待确认指令 | 对话生成的指令，操作员确认后下发 |
| 人工干预 | 手动下发指令（急停二次确认）|

## 三、多路视频流检测

单个 YOLO 模型共享检测多路视频源：

```
本机摄像头(0) ─┐
RTSP摄像头2  ─┼→ 共享单YOLO → 每路独立结果 + 标注帧
预录视频3    ─┘
```

- 视频源支持：本机摄像头 / RTSP / 视频文件
- 任意一路报警 → 触发紧急事件
- 检测结果带 `source_id` 标签区分来源
- 指挥台可切换查看各路画面

## 四、LLM 调度（核心改进）

### 决策异步化
- 调度循环**不再同步调 LLM**（避免 API 超时卡死主循环）
- LLM 决策在**后台线程**执行，调度循环 2 秒一跳始终响应
- 普通事件排队给后台决策线程

### 高危三件套（不依赖 LLM）
检测到火情等高危事件（priority≥2）时立即执行：
1. **急停所有机器狗** — 硬逻辑，不等待 LLM
2. **报火警** — SSE `fire_alarm`，前端全屏红色声光报警
3. **记录事件** — 数据库留档

### 降级机制
- API 不可用 → 自动降级规则模式，后台每 30s 重连
- 状态持久化，前端顶栏显示"LLM 降级中"

## 五、告警双通道

```
检测到告警
    ↓
SSE 即时广播（1ms 推前端，不阻塞）   ← 即时通道
    ↓
异步线程写 alerts 表                 ← 持久通道
    ↓
分级清理：error保留30天 / warning保留7天
```

## 六、运维自愈（运维 agent）

- **诊断器注册表**：绝影 / 感知主机
- **规则诊断优先**：ping/查服务/查数据，每步带标签进事件库
- **两级闸门**：
  - 诊断器声明"高危" 或 闸门关键字命中 → **人工确认**
  - 低危 → 自动修复 + 验证恢复
- **LLM 增强**：规则无结论时 LLM 分析根因给修复命令
- **触发链**：监控告警检测异常 → 发布 `robot_issue` → 自愈诊断

## 七、数据隔离原则

| 数据 | 存储 | 说明 |
|------|------|------|
| 机器人实时状态 | 内存 `_robots` | 毫秒级，变了就用 |
| 事件/决策/告警/对话 | 数据库 | 持久，可回看 |
| SSE 队列 | 内存（有界500）| 防泄漏 |

## 八、修复的功能 Bug

| Bug | 影响 | 修复 |
|-----|------|------|
| LLM 同步阻塞调度循环 | API超时卡死整个系统 | 决策异步化 |

| 事件无限堆积 | events 表膨胀 | 7 天清理 |
